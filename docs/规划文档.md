# 工程规划 · Nuxt Admin CMS 演进路线

> 本规划将《开发文档.md》（设计蓝本）与外部分析对话中的 CMS 架构愿景，映射到当前代码库的实际演进阶段。

## V0.1 CMS Core —— ✅ 已交付

| 能力 | 对应实现 |
|---|---|
| Auth / User | 会话登录（httpOnly Cookie）、users 模块 |
| RBAC | roles 集合 + 权限矩阵 + 通配匹配 + 前后端双层执行 |
| Content Engine | Content Type 建模器 → 动态集合 `ct_*` / 动态 REST / 动态页面 |
| Field System | text/email/password/number/textarea/select/switch/checkbox/date/relation/file/repeater/permissions |
| Relation | relation 跨资源选择器（posts→users） |
| CRUD / REST API | 声明式四页面 + 通用端点（q/sort/page/perPage/bulk） |
| Media | 上传（multipart ≤10MB）/ fs 存储 / 字节回读 / 删除清盘 |
| Admin | Panel + Registry + Schema 引擎 + DataTable + Widget + i18n(zh/en) |
| Draft/Publish 基础 | posts 状态机 + 发布/批量发布动作 |

## V0.2 专业 CMS —— 🚧 分四批

### 批次 A：内容生命周期基础设施 —— ✅ 已交付（2026-08-29）
- [x] 服务端事件总线（`content.before/afterCreate|Update|Delete`、`content.published|restored`）
- [x] 动态内容类型注入生命周期字段（draft/review/scheduled/published/archived + publishedAt/scheduledAt）
- [x] 行内动作：Publish / Unpublish / Schedule（表单弹窗选时间）
- [x] 定时发布调度器（Nitro 插件，15s 轮询，到点自动发布并广播事件）— 实测通过
- [x] 修订历史：更新/删除前自动快照，版本列表 + 一键恢复（带权限校验）— 实测通过
- [x] Webhook：webhooks 资源管理 + 事件订阅分发 + Send Test 直发；**SSRF 防护**（9 个单测锁定：scheme/localhost/私网/IPv6/保留段）
- [x] 通用 CRUD 抽取 `server/utils/crud.ts` + 泛参数化子动作路由（消除静态目录遮蔽缺陷）

### 批次 B：信息组织（下一批）
- Taxonomy（Category/Tag 资源 + 无限级 parent 树 + 与内容类型 relation 绑定）
- Menu 管理（导航结构资源 + 前台渲染契约）
- Settings 系统（General/SEO/Storage 分组；Public/Private 设置隔离，私密项仅环境变量）

### 批次 C：SEO 与预览
- 每条内容 SEO 元字段（title/description/canonical/robots/OG）
- `/sitemap.xml` + `/rss.xml` 路由
- Draft Preview（预览令牌路由，为 Theme 时代打地基）

### 批次 D：自动化收尾
- Webhook 签名（HMAC）与重试队列
- Autosave（表单变更防抖快照）

## V0.3 扩展平台

- 插件 Manifest（server/admin/hooks/permissions/settings 声明式清单）
- 服务端 Hook 注册 API（`onCmsEvent` 面向插件开放）
- Admin 扩展点（Menu/Page/Injection Zones 注册中心）
- Theme 系统（前台 Layout/Blocks/Pages 包，Block Renderer `<component :is>`）
- 迁移脚本约定（内存仓储 → 真实 DB 的 schema 演进）

## V0.4 高级能力

- GraphQL API（Content Engine 已与 REST 解耦，可并行挂载）
- 内容级 i18n（字段级 locale 翻译表）
- Search Adapter（PG FTS → Meilisearch/Typesense）
- Cache Adapter（Memory → Redis → CF）+ 发布事件失效联动
- Storage Adapter 扩展（S3/R2/OSS/COS）
- AI/Analytics 插件

## 验收基线（每个批次）

1. `eslint / typecheck / vitest / build` 四闸门全绿
2. 生产构建端到端实测（curl 往返）
3. 纯函数（URL 安全校验、生命周期判定等）有单测锁定
4. 文档同步（介绍文档对标表 + 开发指南机制说明）
