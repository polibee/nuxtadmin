## 2. 目录结构与职责边界

```
app/
├── admin/                  ★ 框架层——只有框架代码，禁止写业务
│   ├── core/               类型系统(types.ts) · 注册中心(registry.ts) · 事件总线(events.ts) · defineResource
│   ├── panel/              definePanel 定义器
│   ├── panels/             具体面板配置（admin.panel.ts）
│   ├── navigation/         buildNavigation：注册表+权限 → 导航树
│   ├── permissions/        can() 通配匹配器 + useCan()
│   ├── schemas/builders/   DSL 构建器：字段(fields) 布局(layouts) 列(columns)
│   ├── infolists/          详情 Entry 构建器(builders)
│   ├── forms/              schemaToZod 编译器 · useFormSchema 引擎
│   ├── tables/             useResourceTable 服务端表格状态机
│   ├── actions/            defineAction
│   ├── notifications/      notify / notifyError / useToasts
│   ├── modules/            defineModule
│   ├── framework/          ★ 通用渲染组件（DataTable、Resource*Page、ActionHost…）
│   └── ui/                 ★ UI 原子组件（Ui* 前缀命名）
├── modules/                ★ 业务模块目录（users/posts/orders/dashboard）
├── pages/admin/[...path].vue  资源路由分发器
├── plugins/admin.ts        组合根：注册 Panel 与所有模块
├── layouts/default.vue     后台壳（侧栏/顶栏/ActionHost/ToastHost）
└── stores/                 Pinia：auth（会话）· ui（主题/侧栏偏好）

server/
├── api/auth/               login / me / logout
├── api/admin/[resource]/   通用 REST 五件套 + bulk-delete
├── api/admin/stats.get.ts  仪表盘聚合数据
└── utils/                  db(内存仓储) · auth(会话) · resourceConfigs(服务端校验配置)

shared/types/api.ts         前后端共享契约（Paginated/AuthUser/ListQuery…）
tests/unit/                 Vitest 纯函数单测
```

**铁律**

1. 业务代码只出现在 `app/modules/**`，绝不修改 `app/admin/core|framework|ui` 来"顺便满足业务"。
2. 框架层之间依赖方向：`framework → core/engines`，禁止反向。
3. 服务端数据访问只走 `server/utils/db.ts` 暴露的函数（未来换数据库只动这一层）。

## 3. 自动导入清单（无需 import 即可使用）

框架通过 `nuxt.config.ts → imports.dirs` 提供全局 DSL，风格对标 Filament 的全局助手：

| 类别 | 可用名称 |
|---|---|
| 资源/模块/面板 | `defineResource` `defineModule` `definePanel` |
| 注册中心 | `setPanel` `registerModule` `registerResource` `registerWidget` `getPanel` `getResource` `getResources` `getWidgets` `getNavGroups` |
| 字段构建器 | `textInput` `emailInput` `passwordInput` `numberInput` `textarea` `selectInput` `switchInput` `checkboxInput` `dateInput` `relationInput` |
| 布局构建器 | `section` `grid` |
| 列构建器 | `textColumn` `numberColumn` `moneyColumn` `dateColumn` `badgeColumn` `booleanColumn` `actionsColumn` |
| 详情构建器 | `textEntry` `badgeEntry` `booleanEntry` `moneyEntry` `dateEntry` `datetimeEntry` `linkEntry` |
| 动作/通知 | `defineAction` `notify(title, desc?)` `notifyError(title, desc?)` |
| 引擎组合式 | `useFormSchema` `useResourceTable` `useActionRunner` `useCan` `useAuthStore` `useUiStore` `useToasts` |
| 国际化 | `useI18n()` → `{ locale, t }`（`LOCALES` 常量供切换器使用）|
| 事件总线 | `onAdminEvent` `emitAdminEvent` |

组件同理自动注册：`Ui*`（ui 目录）与 framework 目录下的渲染组件。

> 类型不参与自动导入，需要显式引入：`import type { ActionDef } from '~/admin/core/types'`。

### UI 组件清单（`app/admin/ui`，shadcn 风格 · reka-ui 驱动）

| 已内置 | |
|---|---|
| 基础 | UiButton · UiInput · UiTextarea · UiSelect · UiCheckbox · UiSwitch · UiLabel |
| 展示 | UiBadge · UiCard · UiAvatar/UiAvatarFallback · UiSkeleton · UiSeparator · UiSpinner · UiEmpty · UiAlert |

## 4. 核心概念

### 4.1 Registry 注册中心

`app/admin/core/registry.ts` 是框架的"服务容器"。数据流：

```
plugins/admin.ts（组合根）
  └─ registerModule(module)        // 每个模块一次
       ├─ registerResource(r)      // 收集资源 + 记录导航分组顺序
       └─ registerWidget(w)        // 收集仪表盘组件
页面/导航/仪表盘读取：
  getResource(slug) / getNavGroups() / getWidgets() / getPanel()
```

同名资源重复注册会被忽略并警告；分组排序取 `navGroups` 中声明的 `sort`（未声明默认 100）。

### 4.2 Resource

`ResolvedResource` 在运行时保证 `labelPlural` 与 `permissionPrefix` 必有值（后者缺省为 `name`）。可用字段一览：

| 字段 | 说明 |
|---|---|
| `name` | URL slug + API 段，如 `users` |
| `label` / `labelPlural` | 单复数展示名 |
| `icon` | 图标键，见 `app/admin/utils/iconMap.ts`，缺失回退圆形图标 |
| `group` / `sort` | 导航分组与组内排序 |
| `permissionPrefix` | 权限前缀（默认 `name`）|
| `searchable` | 服务端搜索涉及的字段（需与 resourceConfigs 一致）|
| `table()` / `form()` / `infolist()` | 三份 Schema，惰性求值（函数形式便于动态 options）|
| `rowActions` / `bulkActions` | 自定义动作，框架会与默认动作合并 |

### 4.3 Schema 系统

一切 Schema 都是**纯数据节点**，渲染由引擎负责：

- `FieldNode`：`{ type:'field', kind, name, label, ...选项 }`
- 布局：`section(标题或选项, children)` / `grid(列数, children)`，可任意嵌套；`colSpan` 控制字段在 grid 内跨度
- 列：`ColumnMeta.kind ∈ text|number|money|date|badge|boolean|actions`
- 详情：`EntryNode.kind ∈ text|badge|boolean|money|date|datetime|link`

**新增一种字段类型的固定步骤**：

1. `core/types.ts` → `FieldType` 联合加入新 kind；
2. `forms/schemaToZod.ts` → `baseRuleFor()` 给出基础 Zod 规则；若支持 required，在 `compileField()` 加分支（勿把非字符串基类混入 `STRING_BASE_KINDS`）；
3. `framework/FormField.vue` → 加渲染分支；
4. `schemas/builders/fields.ts` → 提供 `xxxInput()` 构建器；
5. `tests/unit/schema-to-zod.test.ts` → 补用例。

### 4.4 Form 引擎

```
schema() ──schemaToZod──▶ ZodObject ──toTypedSchema──▶ vee-validate useForm
FormField 内部 useField(name) 双向绑定；错误消息就地渲染
```

- 编辑页在 record 到达后调用 `form.setValues(record)` 回填；
- 提交经 `submit = handleSubmit(onSubmit)`，`submitting` 状态驱动按钮禁用。

### 4.5 Table 引擎

`useResourceTable(resource)` 是列表页唯一状态源：`q/page/perPage/sortBy/sortDir/items/loading/selection…`。
搜索防抖 300ms；翻页/排序/改每页条数自动重查。

**约定**：组件不得直接改写 prop 内 ref（vue/no-mutating-props），一律调用其变更 API：
`setQuery / setPage / nextPage / prevPage / setPerPage / refresh / toggleSort …`

### 4.6 Action 管线

`useActionRunner.run(action, ctx)` 的固定顺序：

```
权限检查(can) → 有 form? 打开表单弹窗 → 有 confirm? 打开确认弹窗 → execute(handler)
handler 抛错 → notifyError；成功 → 关闭弹窗（成功提示由 handler 自行 notify）
ctx: { resource(必有), record?(行动作), ids?(批量), values?(弹窗表单值) }
```

**刷新约定**：自定义动作改完数据后 `emitAdminEvent('{resource}:refresh')`，列表页已内置监听并重查。参考 posts 的 publish 与 orders 的 mark-shipped。

### 4.7 权限

- 命名约定：`{permissionPrefix}.{view|create|edit|delete}`，模块可自定义额外动作权限（如 `orders.edit` 复用编辑权限）。
- 通配：`*` 全量；`posts.*` 该资源全操作。
- **双层执行**：前端 `useCan()` 过滤导航/按钮/路由（无权进入返回 403 页）；服务端每个 handler 调 `requirePermission(event, 'xxx.yyy')` 强制校验。两者都要写，前者是体验，后者是安全。

### 4.8 Module 与 Panel

```ts
// app/modules/orders/module.ts
export default defineModule({
  name: 'orders',
  resources: [OrderResource],
  navGroups: [{ label: 'Sales', sort: 30 }],   // 分组排序
})
```

新模块在 `app/plugins/admin.ts` 组合根登记一行即可生效。
`definePanel({ id, path, branding, perPage })` 当前注册 `/admin`；多面板时为每个路径建面板配置并在路由层选择。

### 4.9 动态内容类型（Content Type Builder）

用户在 `System → Content Types` 里建模（name + 字段 repeater），保存后：

- 服务端 `resourceConfigs.dynamicConfig()` 把存储定义编译成校验配置，
  通用 REST 自动服务 `ct_{slug}` 集合（类型强转/枚举校验，权限前缀 `content`）；
- 组合根插件（async）在启动时拉取全部定义，经
  `app/modules/content-types/dynamic.ts → buildContentModule()` 注册成
  完整资源（表格列/表单字段/详情条目均由字段类型映射）。

约定：动态资源 name 一律 `ct_` 前缀；slug 服务端生成且不可变；
建模变更后通过行内动作「Reload Registry」触发 `reloadNuxtApp()` 同步侧栏。

### 4.10 媒体库与文件上传

- 存储：Nitro `useStorage('media')`，fs 驱动挂载 `./.data/media`（nuxt.config → nitro.storage）；
- 上传：`POST /api/admin/media/upload`（multipart，字段名 `file`，≤10MB）→ 落盘 + 建 `media` 记录；
- 回读：`GET /api/admin/media/:id/raw`（按记录的 mime 流式返回）；
- 删除：`DELETE /api/admin/media/:id` 覆盖通用删除，同时清理磁盘文件。

客户端 `MediaResource` 通过 `endpoints.create` 把创建表单指向 upload 端点；
`fileInput` 字段使 ResourceFormPage 自动改用 multipart 提交（值中出现 File 时）。

### 4.11 角色与权限矩阵

- 角色 = `roles` 集合（name/key/permissions[]），`key` 创建后不可变（`immutableFields`）；
- 登录会话的 permissions 由 `findRoleByKey` 实时解析——编辑角色后需重载会话（行内动作提供）；
- `permissionsInput` 字段渲染权限矩阵：数据源为注册中心全部资源 × `view|create|edit|delete`，外加 `*` 全量开关。

### 4.12 事件总线 / Webhook / 修订 / 定时发布

**事件**（`server/utils/events.ts`）：通用 CRUD 管线在 `server/utils/crud.ts` 中触发：
`content.beforeCreate/afterCreate/beforeUpdate/afterUpdate/beforeDelete/afterDelete/published/unpublished/restored`。
payload：`{ resource, record?, id?, patch? }`。`before*` 处理器抛错即否决操作。
本地订阅：`onCmsEvent(name, fn)`（返回退订函数）；同一事件自动外发 Webhook。

**Webhook**（`server/utils/webhook.ts`）：`webhooks` 资源 = `{url, events(csv 或 *), enabled, secret}`。
分发时带 `x-webhook-event` 与 `x-webhook-secret` 头，5s 超时、fire-and-forget。
**SSRF 防护**：`parseWebhookTarget`（同步策略：scheme/localhost/私网字面量）+ `resolveSafeWebhookUrl`（DNS 解析后逐 IP 复核）。
测试：`POST /api/admin/webhooks/:id/test` 直发 ping，失败返回 502 带原因。

**修订**（`server/utils/revisions.ts`）：update/delete 前自动 `snapshotRevision`（版本按 `resource:id` 递增）；
`POST /api/admin/revisions/:id/restore` 恢复（先快照当前态；需目标资源 `.edit` 权限）。

**定时发布**（`server/plugins/scheduler.ts`）：Nitro 插件 15s 轮询所有 `ct_*` 集合，
`scheduled && scheduledAt<=now` → 置为 published 并广播 `content.published`。生产换队列/cron。

### 4.13 路由模式：泛参数化子动作

特殊操作一律挂在 `[resource]/[id]/{action}.post.ts`（如 upload/raw/restore/test），
文件内校验 `resource` 名。**不要**为某资源建同名静态目录（如 `media/index.get.ts`）——
Nitro 静态段会遮蔽 `[resource]` 参数路由导致 404；通用逻辑在 `server/utils/crud.ts`。

### 4.14 资源配置钩子与页面覆盖

`ServerResourceConfig` 可选钩子（`server/utils/resourceConfigs.ts`）：

- `enrichList(items)`：列表返回前装饰行 —— 树深度/路径/子计数（taxonomy）、递归计数（menus）、密钥掩码（settings）
- `beforeDelete(record)`：返回错误消息即否决删除（409），如 taxonomy 级联保护
- `validateRecord(data)`：记录级策略校验（webhook SSRF 规则）

**页面覆盖**：`AdminResource.pages.list` 可用自定义组件替换默认列表页
（组合根之外的 Admin 扩展点）——settings 用分组 Tabs 表单编辑器即由此实现。

### 4.15 Settings 公开/私密隔离

- `settings` 集合：`{key, value, type(string|text|number|boolean|secret), group, public}`；
- 管理端列表对 `secret` 掩码（enrichList）；分组编辑页按类型渲染对应控件，
  secret 编辑留空即保持原值；「新增设置」为智能表单——填人读名称自动生成大写下划线键、
  值输入实时探测类型（number/boolean/string）、公开/私密二选一卡片；
- `GET /api/public-settings`（无需鉴权）只返回 `public===true && type!=='secret'`
  的键值对——前台/主题层从这里读取站点配置。

### 4.16 SEO / Sitemap / RSS / Draft Preview

- **SEO 元字段**：`ct_*` 类型自动注入 `seoTitle / seoDescription / canonical / robots(index|noindex)`，
  表单尾部 SEO 分区；`robots=noindex` 的已发布条目不进 sitemap；
- **`GET /sitemap.xml`**：首页 + 已发布 posts（`/blog/{slug}`）+ 已发布动态条目
  （`/{type-slug}/{id}`，主题层落地后替换为真实路由）；origin 取设置 `SITE_URL`；
- **`GET /rss.xml`**：最新 50 篇已发布 posts，频道元数据取自公开设置；
- **Draft Preview**：行内动作 Preview（posts/动态类型，未发布态可见）→
  `POST /api/admin/preview` 换取 15 分钟令牌 URL → `/preview/{resource}/{id}?t=…`
  渲染独立 noindex HTML 预览页。令牌为内存实现，生产换签名 JWT。

⚠️ **server 端坑**：跨文件使用 `server/utils/*` 的导出必须**显式 import**（如 db 的
`getCollection/listCollectionNames`）。依赖 nitro 自动导入时可能产生模块第二实例，
表现为「同一进程里 API 写的数据，另一个 handler 读不到」。

### 4.17 富文本 / Autosave / Webhook 签名与重试

- **`richtext` 字段**：`richTextInput(name, label)` → Tiptap v3（StarterKit）编辑器，
  存储标准 HTML；空内容归一化为 `''`（避免 `<p></p>` 绕过必填校验）；SSR 安全。
  内容类型建模器可选 Rich Text 字段（服务端按 string 存储、不进搜索列）。
- **Autosave**：编辑表单 1.5s 防抖 → `POST /api/admin/autosave`
  `{resource,id,values}`（按 用户×资源×记录 隔离，需 `.edit` 权限）；
  `GET ?resource=&id=[&discard=1]` 读取/丢弃；表单页自动展示「未保存草稿」横幅，
  恢复/丢弃均为显式操作，提交成功后自动清理。内存实现，重启即清。
- **Webhook 签名**：配置 `secret` 的 hook，每个请求携带
  `x-webhook-signature: sha256=HMAC_SHA256(secret, 精确JSON体)`；
  接收方用同一 secret 对原始 body 重算比对（常量时间比较更佳）。
- **重试队列**：投递失败（网络/超时/HTTP≥400）自动入队，退避 1m/5m/15m/60m，
  4 次后丢弃并记日志；调度器每 15s 排空。内存实现，重启即清。

### 4.18 邮件服务（SMTP / 阿里云 / Resend）

- **驱动契约**：`server/utils/mail.ts → sendMail(to, subject, html)`，按 settings 中的
  `EMAIL_PROVIDER`（smtp|aliyun|resend）分发；凭据 settings 集合存储（secret 掩码），
  环境变量（`MAIL_*`）优先覆盖，源码零凭据。
- **阿里云 DirectMail**：按区域预设 SMTP 端点（杭州/新加坡/弗吉尼亚/法兰克福，465 SSL），
  凭据为控制台发信地址 + SMTP 密码；区域白名单在写入前校验。
- **Resend**：HTTP API `POST https://api.resend.com/emails`，Bearer key 仅服务端。
- **配置面板**：Settings → Email 分组为专属面板（provider 卡片/区域下拉/测试发送）；
  端点 `GET|POST /api/admin/mail/config`（密钥只回 hasPass/hasKey）与
  `POST /api/admin/mail/test`（缺配置 502 带原因，非法收件人 422）。
- **编辑器弹窗**：链接/图片/颜色为受控 Dialog（URL 校验、取色器+色板、alt 字段）。

## 5. 实战：从零新建 products 模块

1. **客户端资源**：`app/modules/products/admin/ProductResource.ts`（写法见介绍文档示例）。
2. **模块入口**：`app/modules/products/module.ts`：

```ts
import ProductResource from './admin/ProductResource'
export default defineModule({
  name: 'products',
  resources: [ProductResource],
  navGroups: [{ label: 'Catalog', sort: 40 }],
})
```

3. **服务端校验配置**（关键！漏掉则写入被 404 拒绝）：`server/utils/resourceConfigs.ts`：

```ts
products: {
  label: 'Product',
  searchable: ['name'],
  permissionPrefix: 'products',
  fields: {
    name: { type: 'string', required: true },
    price: { type: 'number', required: true },
    status: { type: 'string', enum: ['active', 'archived'] },
  },
},
```

4. **注册模块**：`plugins/admin.ts` 数组加入 products。
5. **验证**：登录后访问四个页面；用 viewer 账号确认越权被拦；跑 `npm test && npm run lint && npm run typecheck && npm run build`。

## 6. 服务端 API 参考

鉴权方式：httpOnly Cookie `admin_session`（登录后自动携带）。未授权返回 401，越权 403，参数错误 422。

| 方法 & 路径 | 说明 | 权限 |
|---|---|---|
| `POST /api/auth/login` | `{email,password}` → 设置会话 Cookie | 公开 |
| `GET /api/auth/me` | 当前用户 `{id,name,email,role,permissions[]}` | 登录 |
| `POST /api/auth/logout` | 注销 | 登录 |
| `GET /api/admin/:resource` | 列表。查询参数 `q,page,perPage(≤200),sortBy,sortDir` → `Paginated<T>` | `{prefix}.view` |
| `POST /api/admin/:resource` | 创建，按 fields 校验（required 生效）| `{prefix}.create` |
| `GET /api/admin/:resource/:id` | 详情 | `{prefix}.view` |
| `PUT /api/admin/:resource/:id` | 部分更新（仅接受已知字段）| `{prefix}.edit` |
| `DELETE /api/admin/:resource/:id` | 单条删除 | `{prefix}.delete` |
| `POST /api/admin/:resource/bulk-delete` | `{ids:number[]}` → `{removed}` | `{prefix}.delete` |
| `GET /api/admin/stats` | 仪表盘聚合计数/营收序列/最近订单 | 登录 |
| `POST /api/admin/media/upload` | multipart 上传（字段 `file`，≤10MB）→ media 记录 | `media.create` |
| `GET /api/admin/media/:id/raw` | 流式回读上传文件字节 | `media.view` |
| `POST /api/admin/webhooks/:id/test` | 直发 ping 测试（失败 502 带原因） | `webhooks.edit` |
| `POST /api/admin/revisions/:id/restore` | 恢复快照（先快照当前态） | 目标资源 `.edit` |
| `POST /api/admin/ct_{slug}` 等 | 动态内容类型 REST（同通用端点，权限前缀 `content`） | `content.*` |

事件清单（Webhook `events` 可订阅，csv）：`content.afterCreate` `content.afterUpdate`
`content.beforeDelete` `content.afterDelete` `content.published` `content.restored` `webhook.test`
（`beforeCreate/beforeUpdate/beforeDelete` 为本地 Hook 专用否决点，不外发）。

统一响应形状：成功直接返回数据；失败返回 Nitro 错误对象 `{error,url,statusCode,statusMessage}`。

## 8. 编码规范要点

- 风格由 ESLint（@stylistic）强制：1tbs 大括号、无尾逗号、箭头单参不加括号等，`npx eslint . --fix` 可解决大部分。
- 组件命名：UI 原子件 `Ui*.vue`（admin/ui），框架级复合组件语义命名（admin/framework）。
- 服务端工具函数的事件参数类型使用 `type H3Evt = Parameters<typeof getCookie>[0]` 反推，**不要** `import { H3Event } from 'h3'`（存在 h3 双版本类型冲突，详见审计报告）。
- Vue 模板中禁止 `v-model="expr as Type"`（生产构建失败）；需要时用计算属性包装。
- 提交信息建议遵循 `feat|fix|refactor|docs|test|chore(scope): summary`。
