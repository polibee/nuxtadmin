# Nuxt Admin · 介绍文档

> 参考 Laravel Filament 设计思想，基于 **Nuxt 4 + Vue 3.5 + TypeScript** 打造的可扩展后台管理框架。
> 它不是一套页面模板，而是一个框架：业务以「声明式资源」接入，增删改查界面由引擎自动生成。

---

## 一、为什么需要它

传统后台开发中，每个管理模块都在重复回答同样的问题：

- 列表页怎么分页、搜索、排序？
- 表单怎么校验、回显、提交？
- 删除要不要二次确认？批量操作怎么做？
- 导航、权限、通知怎么统一？

本项目把这些问题的答案沉淀为**框架能力**。开发者只需声明"一个资源有什么字段、什么状态"，其余由引擎完成——正如 Filament 之于 Laravel。

| 传统方式 | 本框架 |
|---|---|
| 每个模块手写列表页 | 声明列配置，自动获得搜索/排序/分页/批量操作/CSV 导出 |
| 每个模块手写表单与校验 | 声明字段，Zod 校验规则自动编译 |
| 散落的 `@click` 与弹窗逻辑 | 统一 Action 对象：权限 → 表单弹窗 → 确认弹窗 → 执行 → 通知 |
| 权限判断散落 UI 各处 | `can()` 通配匹配，导航/按钮/API 三层一致 |
| 业务代码与框架耦合 | 模块化注册，业务永不污染核心 |

## 二、核心特性

### 🔧 声明式资源（Resource）
一个 TS 文件描述资源的名称、图标、分组、表格列、表单字段、详情条目，即自动生成四个标准页面：
`列表 / 创建 / 详情 / 编辑`。

### 📐 Schema 即数据
字段、布局、列、详情条目全部是**纯数据对象**（非组件树），因此同一份 Schema 可被表单渲染器、Infolist 渲染器乃至未来的 CLI/文档工具复用。

### 📋 表格引擎（基于 TanStack Table Vue）
全局搜索（防抖）、点击排序（服务端驱动）、每页条数切换、行选择与批量操作、行内下拉动作、CSV 导出、空态/加载态。

### 📝 表单引擎（VeeValidate + Zod）
十类字段开箱即用：text / email / password / number / textarea / select / switch / checkbox / date / relation（关联资源选择器）。校验规则从 Schema 自动编译，错误信息就地展示。

### ⚡ 动作系统（Action）
`defineAction` 描述一个动作的标签、图标、所需权限、确认文案、可选弹窗表单和处理器。执行管线统一处理：权限检查 → 弹窗表单 → 二次确认 → 执行 → 失败通知。

### 🧩 模块化（Module）与多面板（Panel）
业务以 `defineModule` 打包（资源 + Widget + 导航分组），在组合根一处注册。
`definePanel` 支持未来派生 `/admin`、`/partner` 等多个独立面板空间。

### 🛡️ 双层权限体系
User → Role → Permission，支持通配（`*`、`posts.*`）。前端控制可见性，服务端 `requirePermission()` 强制执行——**隐藏按钮从来不是安全边界**。

### 📊 仪表盘 Widget
统计卡片、SVG 营收图、最近订单等 Widget 经注册中心挂载，按权限过滤、按跨度布局。

### 🎭 RBAC 角色管理（权限矩阵）
角色是一等资源：`roles` 模块提供权限矩阵编辑器（勾选 `资源.动作` 或全量 `*`），登录会话的权限由 roles 集合实时解析——改完角色，重载即生效。

### 🖼️ 媒体库与文件上传
`media` 模块：multipart 上传（≤10MB）、缩略图列、字节回读、删除时同步清理磁盘存储（Nitro fs 挂载 `.data/media`）。

### 🧱 内容类型建模器（Strapi 式）
在后台可视化创建内容类型（字段名/标签/类型/必填/枚举选项），保存后**自动生成**：
- 动态导航资源（`Content` 分组）与四个标准页面
- 动态 REST API（`/api/admin/ct_{slug}`，含类型强转与枚举校验）
- 无需重启、无需写代码

### ✍️ Tiptap 富文本编辑器
posts 与内容类型建模器内置 `richtext` 字段：14 项格式化工具栏（标题/列表/引用/代码块/链接/分隔线/撤销重做），
SSR 安全，空内容归一化，存储标准 HTML。

### 🔄 内容生命周期与定时发布
动态内容自带 `draft → review → scheduled → published → archived` 状态机：
行内动作 Publish / Unpublish / Schedule（时间弹窗）；Nitro 调度器每 15s 扫描，
到点自动发布并广播事件。默认创建即 Draft。

### 📜 修订历史
更新/删除前自动快照（版本递增），System → Revisions 列表查看，
一键 Restore 回滚（恢复前再快照当前态；权限按目标资源 `.edit` 校验）。

### 🪝 事件总线与 Webhook
服务端生命周期事件（`content.afterCreate/afterUpdate/beforeDelete/published/restored…`）
同时驱动本地 Hook 与出站 Webhook；`webhooks` 资源管理订阅（csv 事件名或 `*`），
Send Test 直发 ping。**HMAC-SHA256 签名**（`x-webhook-signature`）+ 失败指数退避重试（1m/5m/15m/60m）。
**内置 SSRF 防护**：仅 http/https，拒绝 localhost/环回/私有/保留地址，
域名经 DNS 解析后逐 IP 复核。

### 💾 Autosave
编辑表单 1.5s 防抖自动保存草稿（按 用户×资源×记录 隔离）；
重新打开时提示「未保存草稿」，一键恢复或丢弃；提交成功自动清理。

### 🗂️ Taxonomy（无限级分类树）
Term 资源统一承载 Category/Tag：`parentId` 自关联形成无限级层级，
列表自动富化 depth/path/子计数并以树形缩进展示；含子节点的 Term 删除被拦截（409）。

### 🧭 Menu 管理
菜单 = 命名结构（location: header/footer/custom），条目为**嵌套可重复字段**（两级可视化编辑），
服务端递归清洗与计数，前台可直接消费 JSON 结构。

### ⚙️ Settings 系统（公开/私密隔离）
按分组的可视化表单编辑（General/Blog/Email/… 每组一张表单一次保存）；
`public` 标记 + `secret` 类型双重隔离：`GET /api/public-settings` 只暴露公开且非密钥的键值，
密钥在管理列表中掩码显示；新增/删除设置在分组页内完成。

### 🔍 SEO 引擎与订阅
动态内容自带 SEO 元字段（seoTitle/描述/canonical/robots）；
`/sitemap.xml` 与 `/rss.xml` 开箱即用，noindex 条目自动排除，站点元数据取自公开设置。

### 👀 Draft Preview
未发布条目一键生成 15 分钟有效的预览链接，打开即是渲染好的独立页面
（noindex，不可被搜索引擎收录）——Strapi 的内容引擎 + WordPress 的预览体验。

### 🌐 界面国际化
轻量 i18n（中文默认 / English），Cookie 持久化，顶栏一键切换；资源标签属于项目内容，由作者自定义。

## 四、架构总览

```
┌─────────────────────────────────────────────┐
│ Application   app/pages · layouts · plugins │  组合根：注册 Panel 与模块
├─────────────────────────────────────────────┤
│ Business      app/modules/users/posts/...   │  业务模块（可插拔）
├─────────────────────────────────────────────┤
│ Admin Core    app/admin/core·panel·registry  │  类型系统 · 注册中心 · 事件总线
│               permissions · navigation       │
├─────────────────────────────────────────────┤
│ Engines       schemas(builders) · forms      │  Schema DSL + 渲染引擎
│               tables · actions · widgets     │
├─────────────────────────────────────────────┤
│ Data          server/api · utils(db/auth)    │  Nitro REST + 校验 + 会话
└─────────────────────────────────────────────┘
```

数据流：`Page → composable(useResourceTable/useFormSchema) → /api/admin/:resource → 校验(resourceConfigs) → 仓储(db) `。

## 五、快速开始

```bash
npm install
npm run dev          # http://localhost:3000
```

演示账号（密码均为 `password`）：

| 账号 | 角色 | 能力 |
|---|---|---|
| `admin@demo.dev` | Administrator | 全部权限 |
| `editor@demo.dev` | Editor | 内容/媒体/内容类型管理，订单用户只读 |
| `viewer@demo.dev` | Viewer | 全局只读 |

> 登录后建议依次体验：切换语言与暗色主题、在 **System → Roles** 勾选权限矩阵、**Media Library** 上传一张图、在 **System → Content Types** 建一个类型然后看侧栏 `Content` 分组出现它的页面、用 viewer 账号观察按钮消失与越权 403。

### 一个资源 = 四个页面

```ts
export default defineResource({
  name: 'products', label: 'Product', labelPlural: 'Products',
  icon: 'package', group: 'Catalog', searchable: ['name'],

  table: () => [
    textColumn('name', 'Name', { sortable: true }),
    moneyColumn('price', 'Price'),
    badgeColumn('status', 'Status', {
      active: { label: 'Active', variant: 'success' },
      archived: { label: 'Archived', variant: 'secondary' }
    }),
  ],
  form: () => [
    section('General', [grid(2, [
      textInput('name', 'Name', { required: true }),
      numberInput('price', 'Price', { required: true, min: 0, step: 0.01 }),
    ])]),
  ],
})
```

自动获得：

```
/admin/products            列表
/admin/products/create     创建
/admin/products/:id        详情
/admin/products/:id/edit   编辑
```
